# 문제 해결

## 오류

| Status | 언제 | 할 일 |
|--------|------|-------|
| 401 `API Key required` | `Authorization` 헤더가 없음 | `Bearer {API_KEY}`를 넣습니다. |
| 401 `Invalid API Key` | 키가 틀리거나 지워짐 | 화면에서 키를 다시 확인합니다. |
| 403 | 키를 만든 계정에 역할이 없거나, 역할에 필요한 권한([표](/open-api/ontology-chat#endpoints))이 없음 | 그 계정의 역할과 권한을 확인합니다. |
| 404 | AOS가 v0.84.0보다 낮아 챗 API가 없음 | 버전을 확인합니다. |
| 409 | 같은 대화의 앞 턴이 아직 도는 중 | 앞 턴이 끝난 뒤 다시 보내거나, `chat_id` 없이 보내 대화를 나눕니다. |
| 200 · `status: failed` | 턴 실행 중 오류. `error.code`가 `chat_busy`면 같은 대화에 요청이 겹침, `stream_interrupted`면 서버 안 연결이 끊김 | `chat_busy`는 잠시 뒤 다시 보내고, 그 밖에는 `error.message`와 함께 문의합니다. |

엔드포인트별 400 · 404 · 409 상황은 각 문서의 에러 표를 참고하세요.

문의하실 때는 **AOS 버전, HTTP 상태, 응답 본문**(`message` · `traceId` 또는 `error`)을 함께 알려 주세요.

## passport 오류

passport는 API Key를 만든 사람의 권한 정보입니다. 서버가 API Key 요청에 이 정보를 붙여 에이전트까지 넘기고, 챗 API는 이것이 있어야 동작합니다. 온톨로지 쿼리나 Work 실행은 되는데 챗만 passport 오류(403)가 난다면 아래 경우를 차례로 봅니다.

| 경우 | 증상 | 할 일 |
|------|------|-------|
| 서버 설정 `AUTHZ_PASSPORT_ENABLED`가 꺼져 있음 | 키에 passport가 붙지 않아 챗만 거절됩니다. Work 실행은 이 경우에도 지나갈 수 있습니다. | 온프렘 운영 담당과 설정값을 확인합니다. |
| 만든 사람 정보가 없는 예전 키 | 챗이 거절합니다. | 화면에서 키를 새로 발급받아 씁니다. |
| 키를 만든 계정의 역할에 채팅 권한이 없음 | 403 | 역할에 `chat` create · read 권한을 줍니다. |

## 구조화된 결과가 필요할 때

챗은 사람이 읽는 자연어로 답하므로, 정해진 컬럼으로 결과를 받기에는 맞지 않습니다. LLM 판단 결과를 컬럼으로 받으려면 원하는 컬럼을 워크플로 마지막 단계의 출력으로 만들고, [Work 실행 API](/open-api/works/run-work)(`POST /open/v1/works/{workKey}/run`)로 받는 방법을 권합니다.

`workKey`는 워크플로 상세 화면의 제목 아래 경로에서 `/`를 뺀 값입니다.
